# SCTA 工程升级

升级基于 `7ac08dc` 中已提交的网站实现。线上抽查确认了 `www.scta.cc` 的静态缓存和已发布的徽章设计。工作区里另有一套进行中的 3D 徽章实现，本次分支从已提交版本开始。

## 架构决定

- `src/i18n` 统一路由、请求语言、导航和页面元数据。中文由无前缀 URL 确定，英语和日语分别使用 `/en` 与 `/ja`。已有显式中文前缀和语言 sitemap 路径保留重定向。页面参数驱动 HTML lang，切语沿用当前 pathname、原始查询串和片段。活动正文、海报、校名和历史介绍沿用原始资料，并给中文资料加上语言标记。
- 活动时间通过 `activity-date.ts` 按 `Asia/Shanghai` 格式化。列表和详情使用同一套日期规则。界面字典由 TypeScript 检查 key，CI 检查三语覆盖、ICU 参数类型、选择分支与各语言的复数类别。
- `src/lib/content.ts` 为每个构建进程复用 Markdown 索引、时间排序和按需解析结果。列表读取摘要，详情读取完整 HTML。摘要沿用原版去标签、压缩空白和截取 120 字符的规则。方案库筛选只接收分类与已生成的卡片。
- `src/lib/posters.ts` 从文件读取 EXIF 修正后的宽高，用文件内容哈希更新优化图缓存键。列表首份 HTML 已有最终比例，省去页面端原图探测。图像选择采用实际列宽和 DPR，首页主标志和列表首张海报预加载，活动列表首排另外两张由 HTML 直接发起请求，其余海报使用原生懒加载。
- `ResponsiveColumns` 保留旧库按索引取模分列的规则。原库桌面初始 3 列，手机 hydration 后重排为 2 列。只换成监听媒体查询的客户端组件依然要在首屏重组。CSS Columns 和等行 Grid 会改变列归属或独立列高。当前方案在同一份 HTML 给出两种列结构，由 CSS 立即选择，每张卡片在 RSC 数据中复用一次。
- 首页静态内容移至 Server Components。全站 Provider 只下发导航和错误界面所需消息，徽章、学校和方案筛选各取自己的消息。首页主徽标沿用原弹簧曲线的采样进入，CSS 在 hydration 前启动动画。持续装饰动画也由 CSS 播放，并在离屏时暂停。Framer Motion 的精简动画特性提供其余进入和弹簧交互。
- 站点字符子集来自与基准相同的 Noto Sans SC 2.004-H2。采用单份可变字体样式和原字体回退，避免发出大量 CJK 分片请求。方案文字封面使用得意黑同版子集，保留原字体回退。两份子集的 OFL 随代码保存。 [Next.js 字体模块](https://nextjs.org/docs/15/app/api-reference/components/font) · [Google Fonts Noto Sans SC](https://github.com/google/fonts/tree/main/ofl/notosanssc) · [得意黑](https://github.com/atelier-anchor/smiley-sans)

路由保留静态生成，未知页面才进入 404 边界。错误文件和请求语言的行为按已安装的 Next.js 15.5 与 next-intl 4.9 验证。 [next-intl 静态路由](https://next-intl.dev/docs/routing/setup) · [请求配置](https://next-intl.dev/docs/usage/configuration) · [Next.js 15 缺页处理](https://nextjs.org/docs/15/app/api-reference/file-conventions/not-found)

## 测量

采集工具、原始性能记录、Chrome trace 和截图随交付证据保存。测试以两份 Node 22.23.5 本地生产构建为对象，固定 Chromium 143、视口、DPR、配色和缓存策略。390 × 844 使用 DPR 2，1440 × 900 使用 DPR 1。弱网采用约 1.6 Mbps 下载、0.75 Mbps 上传、150 ms 延迟和 4 倍 CPU 降速。常见路由的冷与热缓存各重复三次，表格用中位数。冷表示新浏览器上下文，热表示同一上下文再次打开。CDP 测量复用截图测试已预热的本机优化器。优化器自身的冷、热缓存另用同一 AVIF URL 连续请求核查。

页面网络传输由 CDP 记录。Lighthouse 使用同版本 Chrome 和默认 Mobile 模拟配置，其指标与 CDP 弱网样本各自比较。单独用 `next build --profile` 与临时卡片计数器记录渲染，性能表使用普通生产构建。

| 390 px 活动列表 | 3.81 → 1.37 | 4.52 → 1.92 | 0.0037 → 0 | 89 → 35 | 6.15 → 1.10 |

- 390 px 活动列表此前请求 28 张原图和 16 张优化图，现在发出 13 张优化图请求，海报传输从 4.65 MB 降到 275 KB。首页瀑布流实测 6 张原图和 6 张优化图变为 4 张优化图，海报传输从 1.07 MB 降到 91 KB。CSS 在首份 HTML 选出两列，原先 hydration 后三变二的重排消失。
- 390 px 首页字体请求从 20 个变为 1 个，传输从 1.12 MB 降到 540 KB。三语分别访问时都实测为一份主字体。方案库字体由 2.18 MB 降到 552 KB。抽查的 208 组字形轮廓和字宽与原字体一致。
- 1440 px 弱网活动列表的脚本时间从 352 ms 降到 184 ms，布局从 1186 ms 降到 180 ms。390 px 活动列表的脚本时间从 398 ms 降到 171 ms。采样区间内的首页 TBT 中位数为手机 8 → 32 ms、桌面 0 → 35 ms。较早的首绘也改变了 TBT 计时区间。
- 卡片函数计数在手机首页和列表分别为 15 → 0、71 → 0，在桌面为 11 → 0、53 → 0。卡片由服务端生成，内层图片和链接保留客户端行为。
- Next.js 报告的 First Load JS 为首页 169 → 153 KB、活动列表 162 → 125 KB、方案库 127 → 125 KB、徽章列表 149 → 128 KB。活动和方案详情由 111 增至 125 KB，单枚徽章详情由 149 增至 155 KB。此项使用构建统计。CDP 实际接收的 390 px 活动列表 JS 为 187 → 168 KB，CSS 为 139 → 49 KB。
- 首页和活动列表的 Flight 数据取消了 `contentHtml` 字段。双布局和服务端标记使活动列表 HTML gzip 体积从 33.63 增至 42.70 KB，其 RSC gzip 体积由 19.44 降至 14.55 KB。首页 HTML gzip 由 20.63 增至 30.62 KB，RSC gzip 由 8.42 增至 14.24 KB。弱网时活动列表预取由手机 7 → 1、桌面 8 → 2 次。
- 热缓存下，活动列表弱网 LCP 在手机由 0.77 增至 0.83 秒，在桌面由 0.58 增至 1.05 秒。热缓存的布局偏移降到 0，桌面实际传输由 73.32 降到 23 KB。Node 22 当次全新生产构建耗时 16.75 → 17.80 秒。浏览器性能收益与构建耗时分别量化。

Lighthouse 12.8 的默认移动模拟在 412 px 另采集一组配对样本。首页 LCP 11.58 → 5.86 秒、活动列表 10.90 → 6.68 秒，两个模拟值仍高于 2.5 秒。两份交付版 trace 将剩余时间分别定位到首绘样式链路和海报绘制等待。Lighthouse 模拟在采集后预测退化条件，主表的 CDP 数据来自浏览器直接施加的网络和 CPU 限速。 [Lighthouse 限速方式](https://github.com/GoogleChrome/lighthouse/blob/main/docs/throttling.md)

在 390 px 固定滚动实验中，旧版与新版的帧间隔 p95 分别为约 10.2、10.1 ms。`content-visibility:auto` 使初始文档高 5813 px，展开后为 5243 px，帧间隔与现行方案相当。`contain:layout style` 保留 5243 px 高度，收益处于噪声范围。当前采用原生滚动，四倍 CPU 降速下各组 129 帧均未出现 25 ms 以上的间隔。另一项三次触屏采样中，菜单点击到可用的中位数为 232 → 156 ms，列表海报点击到详情标题绘制为 77 → 88 ms。后两项均为本机操作时延。

第一个可运行版本先解决原图探测和首份 HTML 的列数。下一轮根据 trace 合并字体请求并减少首页 hydration。最后一轮把大屏首排海报的加载提前，并用 CSS 启动桌面首页徽标进入动画，减少了 LCP 对客户端执行的等待。单独提高首页徽标和列表前三图的抓取优先级后，首页 LCP 中位数变化小于 20 ms。活动列表在 412 px 由 1.82 增至 2.02 秒，在 1440 px 由 2.22 增至 2.31 秒，各重复三次。最终保留首图预加载和其余首排图常规立即加载。

## 验收

- Chromium 覆盖 320–1920 CSS px 的 14 个宽度、三种语言和浅深配色，执行 348 组布局检查。WebKit 26 另执行 210 组。视觉基线与交付版各记录 108 组页面截图及布局。桌面中文在 641、768、1024、1440、1920 px 执行 204 次卡片对位，比较列归属、列内顺序、海报、图文区域和卡片边界框，最大坐标差为 0 CSS px。1440 px 下复旦大学弹窗在两种配色中逐像素一致。海报取样分辨率和纠正后的导航高亮产生了小范围像素差，差分图随证据保存。
- 三语共 27 条直接访问路径核验 `lang`、canonical、hreflang 和预渲染响应。切语测试覆盖编码 slug、重复且有序的 query、锚点、刷新、前进和后退。另行实测三语缺页和隔离的 500 错误页，以及洛杉矶浏览器时区下的上海日期。
- 390 px 首份 HTML 已给出双列和具体海报比例，关闭 JavaScript 与启用 JavaScript 时首张 178 px 海报框尺寸一致。DPR 2 和 3 下浏览器分别选中 400 和 640 像素的海报，匹配 178 CSS px 的实际列宽。断开优化图请求后比例仍固定。支持缺档和损坏文件的 16:9 文字封面。注入 EXIF orientation 6 的样本显示为 `120 / 72`，同名文件替换后改为 `90 / 40`，缓存键同步变化。优化服务同一 AVIF 请求从 MISS 变为 HIT。
- 针对触屏走通了从列表点开详情再返回原滚动位置、学校弹窗焦点恢复、方案筛选及徽章旋转和竖向滚动。英语顶栏在 768–1023 px 沿用抽屉入口，给较长的本地化菜单留出空间。短横屏、320 px 的 200% 文字放大和暗色模式均在运行页面上检查。动画单独核对桌面卡片的 0.5 秒进入、100 ms 逐卡延迟、1.05 倍悬停缩放、装饰离屏暂停和减少动态效果。
- `npm ci`、`npm run check:i18n`、`npm run typecheck`、`npm run lint` 与 `npm run build` 在 Node 22 通过。新版生成 112 份静态页面，旧版 111 份。公开首页、活动、方案和隐藏徽章的三语路径都为 SSG，根 sitemap 也转为静态。未知路由的 404 由动态兜底返回。 Next.js 文件追踪以仓库根目录为界，上级目录的锁文件不会改变追踪范围。

### 线上观测

本地到公开首页的三次请求都得到 Vercel CDN `HIT`，TTFB 为 356–384 ms。大陆公开探针的武汉联通、嘉兴移动节点分别约 1.03 s、1.26 s 完成，成都阿里云样本 TCP 超时。探针有各自的网络位置和代理条件，结果是单次基线。线上 Analytics 与 Speed Insights 的 gzip 脚本分别约 2.0 KB、7.3 KB，交付版在 Vercel 继续加载这两项遥测。真实用户 INP 暂无可读取数据，发布后的性能需要实际部署采样。 [Globalping 原始测量](https://globalping.io/?measurement=2UcwCx9v6zx1g3gFp00021Z0b)

## 复现

```sh
npm ci
npm run check:i18n
npm run typecheck
npm run lint
npm run build
npm run start -- --hostname localhost --port 3000
```

`localhost` 使 Next 自托管内部重写与启动主机一致。视觉回归将循环装饰固定在同一位置，另行测试动画时长和交互。可用证据包内的脚本重跑两份生产构建的网络和坐标采集。

可选的字体刷新使用 Python 的 FontTools 和 Brotli，常规构建直接使用仓库中的 WOFF2。脚本会核对 Noto 源文件内容哈希。

```sh
python3 scripts/build-font-subsets.py '/local/path/NotoSansSC[wght].ttf'
```
